キーボードショートカットの集中管理に続き、本格的なデスクトップアプリケーション（Tauri や Electron など）へとスケールさせるために必要となる「フロントエンド側のコアモジュール（サービス層）」をまとめました。

すでに洗練された `NavBar.svelte` や状態管理の仕組みが構築されているため、これらと密接に連携する以下のモジュール群を整備していくと、ネイティブアプリとしての完成度が一段と高まります。

---

## 1. ウィンドウ操作・ライフサイクルマネージャー

現在の `NavBar.svelte` は `DesktopApp` というタイトルや中央コンテンツ 、右側のアクション を持つカスタムタイトルバー（フレームレスウィンドウ）としての役割を担える構造になっています 。これらをOSのウィンドウ枠と連動させるためのモジュールです。

- **主な機能:**
- OS標準の枠を消した際、`NavBar` 側からウィンドウの「最小化」「最大化」「閉じる」をネイティブAPI経由で呼び出す。

- ドラッグによるウィンドウ移動（ウィンドウドラッグ領域）の制御。
- アプリ終了時の「未保存の変更があります。閉じますか？」といったインタラクションのハンドリング。

## 2. テーマ・外観マネージャー (ThemeManager)

`NavBar.svelte` には `dark:bg-gray-900` や `dark:text-white` といった、Tailwind CSSによるダークモード用のクラスがすでに組み込まれています 。これらをシステム（OS）の設定と連動させるコアモジュールが必要です。

- **主な機能:**
- OSのテーマ設定（ライト／ダーク）の変更をリアルタイムに検知して、`document.documentElement` の `dark` クラスを動的に切り替える 。

- ユーザーによる「常にライト」「常にダーク」「システムに同期」の選択状態を管理する。

## 3. 永続化設定マネージャー (ConfigManager)

Webアプリの `localStorage` は、デスクトップアプリにおいては容量制限やアプリのキャッシュクリアによって消去されるリスクがあります。OSの適切なディレクトリ（`AppData` や `Application Support`）にJSON等のファイルとして設定を安全に保存するモジュールが不可欠です。

- **主な機能:**
- ウィンドウのサイズや位置（次回起動時に同じ場所で開くため）の自動保存。
- ユーザー設定（テーマ、ショートカットの割り当て、デフォルトの保存先など）のロードと保存。
- バックエンド側（Rust/Node.js）のローカルファイルシステムと非同期で同期する仕組み。

## 4. 型安全なIPC（プロセス間通信）ブリッジ

フロントエンド（Svelte）とバックエンド（Rust や Node.js などのネイティブ層）の間でデータをやり取りするための通信ラッパーです。

- **主な機能:**
- バックエンドの関数を呼び出す際（ファイルの読み書きや重い計算など）、TypeScriptの型定義を効かせて安全に呼び出す。
- バックエンド側からの非同期イベント（例：「USB機器が接続された」「バックグラウンド処理が完了した」など）をフロントエンド側でリッスンし、Svelteの `$state` へリアクティブに反映する。

## 5. ダイアログ・ファイルシステムサービス

デスクトップアプリにおいて、ファイルの「開く」「保存」はWebブラウザのダウンロードとは異なり、OSネイティブのファイルダイアログを呼び出す必要があります。

- **主な機能:**
- ファイル・フォルダ選択ダイアログの表示と、選択された絶対パスの取得。
- アプリ画面内へのファイルドラッグ＆ドロップ（Dropzone）の検知とパス解析。

## 6. ネイティブUI・通知マネージャー

ブラウザの通知ではなく、OS固有の通知センターや、タスクバー／システムトレイ（常駐アイコン）と連携するためのモジュールです。

- **主な機能:**
- アプリがバックグラウンドにいる状態でのネイティブ通知のプッシュ。
- システムトレイの右クリックメニューの動的制御。
